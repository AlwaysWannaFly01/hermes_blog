## 一、先问一个会被「一本正经胡说」的问题

你问某个大模型：公司去年新出的差旅报销政策，打车费怎么报？它回答得头头是道——流程、限额、部门抬头都对，唯独数字和条款是编的。这正是今天大模型的两块短板：一是幻觉，模型是「预测下一个词」的概率机器，事实以压缩的统计形式存在参数里，缺了就流畅地编；二是知识陈旧，参数里的知识冻结在训练截止日期，再专业的模型也不知道你上周刚发的内部文档。

RAG（Retrieval-Augmented Generation，检索增强生成）就是为这两个痛点而生的。它的思路朴素得近乎「作弊」：让模型别只靠记性，先查资料，再照着资料答。

## 二、什么是 RAG：一句话 + 四步

一句话定义：RAG 把「预训练模型自带的参数化记忆」和「外部向量索引构成的非参数化记忆」组合起来做生成。这个说法来自 2020 年 Lewis 等 12 位作者在 NeurIPS 发表的论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》（arXiv:2005.11401），论文原文写道：RAG 模型「combine pre-trained parametric and non-parametric memory for language generation」。

拆开看，一次 RAG 走四步：

1. 索引（Indexing）：把文档按语义切成块（chunk），用 embedding 模型把每块变成向量，存进向量库（vector store）。
2. 检索（Retrieval）：把用户问题也向量化，用余弦相似度在向量库里找出最相近的前 K 条（Top-K）。
3. 增强（Augmentation）：把检索到的原文片段拼进上下文，作为「外部知识」喂给模型。
4. 生成（Generation）：模型基于「问题 + 检索到的上下文」作答，并附上引用。

用开头的报销例子走一遍：内部政策文档先被切块、向量化、入库；员工问「打车费怎么报」，问题被向量化后在库里命中「差旅报销 30 天内提交票据」那一块；这一块原文被拼进提示词；模型据此回答并附上来源链接。整个过程模型从未「背过」这份政策，却答得准确且有出处。补充一句：LlamaIndex 官方文档把 RAG 拆成 Loading→Indexing→Storing→Querying→Evaluation 五阶段，是把「存储」和「评估」单独拎了出来，本质与四步一致。

这里牵涉的几个核心组件值得先混个脸熟：embedding 模型负责把文本转成数值向量，向量间的距离近似语义相似度；向量库是存向量、查向量的专用数据库（如 Milvus、Pinecone、Qdrant、pgvector）；余弦相似度衡量两向量方向的接近程度；Top-K 就是只取相似度最高的前 K 条；rerank（重排序）则用更精细的模型对初检结果二次打分，把最相关的排到最前面。

理解这四步有一个关键：真正决定答案质量的，往往不是后面的生成模型，而是前面检索到的内容靠不靠谱——检索环节是整条链的上限，垃圾进、垃圾出。这也正是下一节误区反复回到「检索」的原因。

## 三、RAG 为什么有价值

第一，缓解幻觉。幻觉的根源是模型「只靠参数里的统计规律说话」，没有逐条核对真实世界的机制；RAG 给它塞进检索到的原文，等于给答案上了一道「查证」工序。但要先说清楚：这是缓解，不是根除——检索会漏块、生成仍会跑偏，这一点留到误区部分细说。

第二，突破知识时效与私有数据墙。模型知识冻结在训练截止日期；RAG 只需重新索引最新文档就能更新，不必重训。LlamaIndex 文档说得直白：大模型「aren't trained on your data」，RAG 的解法就是「adding your data」——把你的私有数据接进来。比如律师事务所接上内部判例库，问它「类似案例怎么判」，它引用的是本所真实文档，而不是编一个不存在的判例。

第三，可溯源。回答能附上原文片段和链接，人工可核查，这一点对企业尤其关键——回答错了能顺着引用查到是哪份文档出了问题。McKinsey 的企业级工具 Lilli 就是典型：它扫描 40 多个知识源、10 万+ 份文档，每次找出 5 到 7 条最相关内容、总结要点、附链接，一位合伙人自述会议准备「省约 20% 时间」。

第四，更新成本低。改知识 = 重新索引文档（增量、便宜），对比全量微调（昂贵、慢），差距明显。知识天天变，索引天天刷，模型一次都不用重训。

## 四、四个常见误区

误区一：RAG 能彻底消除幻觉。错在哪：检索可能漏掉关键段落，生成阶段仍可能偏离上下文；幻觉只是被「显著缓解」，没有被「根除」。据 Vectara 幻觉榜单（动态数据，截至 2026 年 5 月更新），即便当前最强的模型，摘要短文档时仍有约 2%–10% 不等的幻觉率。正确做法：用 faithfulness（忠实度）等指标持续评测（Ragas，arXiv:2309.15217），并强制回答带引用供人工核查。

误区二：向量检索 = 语义理解。错在哪：embedding 是对「语义相似度」的数值近似，不是真正的理解，对同义改写、跨语言、专有名词、长文档容易漏召回或误命中。正确做法：混合检索（向量 + 关键词 BM25）加 rerank（重排序）精排，补上单一向量检索的盲区。

误区三：RAG 是微调的替代品。错在哪：二者作用维度不同——RAG 管「外部知识接入」（非参数化记忆），微调管「模型参数行为与风格」（参数化记忆），这是 Lewis 论文就划好的界限。正确做法：知识频繁更新、需要溯源用 RAG；固化领域能力、风格用微调；多数场景两者组合。

误区四：切分与检索数量无所谓，检索越多越好。错在哪：chunk 太大稀释语义、太小丢失上下文，直接影响命中率；而上下文窗口有限，Top-K 塞太多无关块只会引入噪声、稀释模型注意力，反而更差。正确做法：按文档结构切块、控制合理大小与重叠，先 rerank 精排再只注入最相关的少量片段。

## 五、小结与入门建议

一句话回顾：RAG 补的是「知识」，不是「聪明」——它给模型接上外部资料库，让答案更准确、更新、可追溯，但不会提升模型本身的推理能力。

什么时候用 RAG？知识频繁更新、需要溯源、要把私有/领域数据接进对话时。什么时候不用？只有固化风格或窄领域能力、且数据稳定时，才优先考虑微调。

入门路径很直接：先用最小 demo 跑通「向量化 + 余弦相似度 + Top-K」的检索这一步（见下），确认能命中对的块；再叠加 rerank 精排，最后用 Ragas 的 faithfulness、context relevance 等指标把「检索质量」和「生成质量」分开评测——因为检索质量是答案质量的上限，检错了，生成必错。一步步加，别一上来就上复杂框架。

最小 demo（检索一步，可直接运行）：

```python
# pip install sentence-transformers
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("all-MiniLM-L6-v2")

docs = [
    "差旅报销需在行程结束后 30 天内提交票据。",
    "年假每年 10 天，可结转至次年 3 月。",
    "办公用品采购单笔超过 500 元需部门经理审批。",
]
query = "出差打车费怎么报销？"

doc_vecs = model.encode(docs)
q_vec = model.encode([query])[0]
sims = np.dot(doc_vecs, q_vec) / (np.linalg.norm(doc_vecs, axis=1) * np.linalg.norm(q_vec))
print(docs[int(np.argmax(sims))])
```

跑通后把命中的句子拼进提示词、交给 LLM，就是一次完整的 RAG。这套范式本身也在演进——从早期朴素的 Naive RAG，到加 rerank、混合检索的 Advanced RAG，再到组件可插拔的 Modular RAG（Gao et al. 综述，arXiv:2312.10997）。但万变不离其宗：先查对资料，再照着答。记住它终究是工具，不是银弹。
